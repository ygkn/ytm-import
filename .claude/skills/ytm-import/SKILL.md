# ytm-import の操作

このリポジトリの `ytm-import` CLI を使って、ユーザーの移行作業を進める。ユーザーは判断と承認だけを行い、コマンドの実行・結果の要約・判断の下書きは Claude が担う。

## 実行方法

- リポジトリのルートで実行する。コマンドは `mise exec -- uv run ytm-import <command>`。`uv` にパスが通っていれば `uv run ytm-import <command>` でもよい。以下では `ytm-import` と略記する。
- 状態は `data/state.sqlite`、ログは `data/ytm-import.log` にある。DB は直接編集せず、必ず CLI を通す。
- 出力はほとんどが JSON。ユーザーへの報告では JSON を貼らず、表や箇条書きに要約する。

## 安全規則（必ず守る）

1. **アカウントへの書き込みは `apply --execute` と `follow --execute` だけ。** これは、この会話の中で次の 3 点をユーザーに示し、ユーザーが明示的に承認した場合にだけ実行する。
   - `whoami` で確認したアカウント名
   - 高評価を付ける曲数（`apply` の dry-run の結果）、またはフォローするアーティストの数と一覧
   - 対象外になる曲数・アーティスト

   以前の承認や、別の目的で得た承認では実行しない。
2. **認証情報を読まない・表示しない。** `~/.config/ytm-import/browser.json` を cat / Read しない。リクエストヘッダーや Cookie をユーザーに貼らせない。認証の設定はユーザー自身が行う（後述）。
3. **判断の記録（`decide` / `accept-mv --execute`）はローカルの変更だけだが、ユーザーの承認を得てから行う。** ユーザーが「確信度の高いものは確認なしで記録してよい」など範囲を指定して任せた場合は、その範囲に限り確認を省いてよい。
4. **照合（`match`）を同時に 2 つ動かさない。** 開始する前に `ps aux | grep "ytm-import"` を確認する。ユーザーが TUI で照合中なら待つ。
5. 迷ったら記録しない。`defer`（後で判断）にするか、ユーザーに聞く。

## 最初に

```sh
ytm-import status
```

- `total` が 0 なら CSV を取り込む：`ytm-import import <Exportify の CSV>`
- Spotify で曲が増えたときも、書き出し直した CSV を同じく `import` する。追加された曲だけが `pending` として加わり、それまでの判断と付与の記録は残る。以降は `match` → 点検 → 適用を、追加分についてだけ行えばよい
- `by_status.pending` / `error` が残っていれば照合が未完了。
- 結果に応じて、以下のどの段階かをユーザーに一言で伝えてから進める。
- `premium_policy` は Premium 会員だけが再生できる曲の扱いを表す。
  - `include`（既定）：追加する
  - `review`：要確認に回す
  - `exclude`：追加しない

  ユーザーが Premium 未加入らしい場合や、変更を希望した場合は、`ytm-import config premium <include|review|exclude>` で変更する。変更すると、保存済みの検索結果から判定がやり直される（通信なし・手動の判断は保持）。

## 1. 照合

```sh
ytm-import match                # 未照合の曲だけ検索（ログイン不要・読み取りのみ）
ytm-import match --retry-open   # 要確認・見つからない曲も再検索（手動の判断は保持）
```

- 2,700 曲で 40 分ほどかかる。**バックグラウンドで実行**し、完了通知を待つ。途中経過を聞かれたら `ytm-import status` を返す。
- 中断しても結果は保存され、再実行すると続きから再開する。
- 照合ロジックを修正した後は、`ytm-import redecide` で保存済みの検索結果から判定だけやり直す（通信なし。手動の判断は変わらない）。

## 2. 点検（誤一致・惜しい未決定）

```sh
ytm-import audit --limit 50
```

グループごとの見方：

| グループ | 意味 | 確認すること |
| --- | --- | --- |
| `auto_title_differs` | 自動一致したが曲名の表記が違う | ライブ／TV サイズ／インスト／別の ver.／別の歌唱者の版を選んでいないか |
| `auto_partial_artists` | アーティストの一部だけ一致 | 歌唱者違いの版（ソロとユニット、feat. の有無）を選んでいないか |
| `auto_credit_tolerated` | ISRC・アルバム・長さの一致を理由に、クレジット表記の違いを許容した | 別人の同名曲でないか |
| `auto_other_album_and_length_gap` | アルバムが違い、長さが 2 秒以上ずれる | 再録・リマスター・別ミックスでないか |
| `near_miss:*` | 未決定のうち、1 項目だけ不一致の曲 | 正解の候補なら pick を提案する |

- 誤りを見つけたら、曲ごとに「何が違うか」と「どうするか（pick / skip / reset）」を表にしてユーザーに提示し、承認後に `decide` で記録する。
- 同じ原因の誤りが複数見つかった場合は、照合ロジックの不具合として報告する（`src/ytm_import/matcher.py` / `textnorm.py`）。修正するかどうかはユーザーに聞く。

## 3. MV 版の一括採用

YouTube Music に音源が無く、公式 MV だけが一致する曲が対象。

```sh
ytm-import accept-mv            # dry-run：対象の一覧
ytm-import accept-mv --execute  # 承認後に確定
```

件数と数例を示し、「MV はイントロや効果音が入ることがある」ことを添えて承認を取る。

## 4. 要確認の曲の判断

```sh
ytm-import review-list --limit 20 --offset 0          # 1 行 1 曲の JSON（候補は順位付き）
ytm-import search <uri> "<検索語>"                    # 候補が無い・不足しているときの再検索（読み取りのみ）
ytm-import add-video <uri> <videoId>...               # Web 検索で見つけた動画を候補に追加（読み取りのみ）
```

20 曲ずつ処理する。各曲について候補の `notes`・`diff`（長さの差、秒）・`type`（audio / MV / UGC）を見て、次の基準で分類する。

| 分類 | 基準 |
| --- | --- |
| pick（確信度高） | 曲名と版の表記が同じで、歌唱者（CV 表記を含む）が同じで、長さの差が 3 秒程度以内。表記揺れ（カタカナと英語、旧名と新名、クレジットの省略）だけが不一致の原因であるもの |
| pick（要確認） | MV 版しか無い、長さが 4〜10 秒違う（ベスト盤とシングル）など、同じ曲ではあるが音源が違う可能性があるもの |
| search | 候補に正解が無さそうなもの。検索語を変えて試す。例：曲名だけ、曲名＋アルバム名、英語表記、`曲名 (TV size)` を外す |
| Web 検索 | `search` でも見つからないもの。WebSearch（`allowed_domains: ["youtube.com", "music.youtube.com"]`）で公式音源を探す。狙うのは `Provided to YouTube by …` の Topic 動画（YouTube Music の音源）。見つけた videoId は `ytm-import add-video <uri> <videoId>` で候補に加え、長さの差と `notes` を確かめてから pick を提案する。Premium 限定の曲やアルバムごと再生できない作品は、ログインしていない検索には出てこないので、この方法でしか見つからないことが多い。ユーザー投稿（UGC）、カバー、MV、ショート版の動画は選ばない |
| skip 提案 | YouTube Music に存在しないもの（カバー・カラオケ・オルゴール・別アーティストの同名曲しか無い） |
| 判断保留 | 同名曲の歌唱者違い（ユニットとソロ、キャラ違い、キャスト違い）や、ライブ版と原曲のどちらか判断できないもの |

特にアニソン・声優・舞台作品では次に注意する。

- 同名曲の歌唱者違い：`(CV.○○)` の人物、`○○ ver.`、ユニット名
- TV サイズ・Off Vocal・ライブ音源
- 劇中歌アルバムとシングルの違い

分類結果は次の形の表でユーザーに提示する。

| # | Spotify | 提案 | 候補 | 理由 |
| --- | --- | --- | --- | --- |

承認された分だけを JSON にまとめ、スクラッチパッドに書いてから記録する。

```sh
ytm-import decide --file <scratchpad>/decisions.json
# [{"uri": "...", "action": "pick", "video_id": "..."}, {"uri": "...", "action": "skip"}, ...]
```

`decide` は全件を検証してから記録する。1 件でも不正があれば何も記録しない。判断保留の曲は `defer` にするか、未決定のまま残して TUI（`ytm-import`）での確認を勧める。TUI では `p` で候補を試聴できる。

## 5. 認証（適用の直前に一度だけ）

ユーザー自身に次の手順で設定してもらう。Claude は Cookie やヘッダーを受け取らない。

1. Chrome の**シークレットウィンドウ**で https://music.youtube.com にログインし、開発者ツール（macOS: ⌥⌘I）の Network タブで `browse` のリクエストを選ぶ。
2. Headers タブの Request Headers で `x-goog-authuser` の値（`0`、`1` など）を確認する。
3. `cookie` の値を右クリック → Copy value でコピーする（Copy request headers でヘッダー全体をコピーしてもよい）。
4. **ログアウトせずに、シークレットウィンドウを閉じる。** 開いたままだとブラウザが Cookie を更新し、コピーした Cookie がすぐ無効になる。
5. Claude Code のプロンプトで次を実行する（`!` で始めるとユーザーのシェルで実行される）：
   `! pbpaste | mise exec -- uv run ytm-import auth --authuser <2 の値>`

`ログイン確認 OK: <アカウント名>` と出れば完了。想定と違うアカウント名なら `--authuser` の番号を変えてやり直してもらう。

うまくいかないとき：

- 「cookie ヘッダーが見つかりません」：クリップボードに Cookie 以外がコピーされている。確認するときは `pbpaste | python3 -c "..."` で**長さ・行数・`SAPISID=` を含むかだけ**を見る。値や先頭の数文字も表示しない。
- 実行中の `401 Unauthorized`、`ログイン確認に失敗しました`、アカウント情報の `KeyError: 'header'`：Cookie が無効になった。手順をやり直してもらい、承認済みの処理を再開する（付与・フォロー済みの分は飛ばされる）。
- `Expecting value: line 1 column 1`：一時的な空の応答。再実行すれば通ることが多い。

## 6. 高評価の適用

```sh
ytm-import apply              # dry-run：件数と先頭・末尾の数例
ytm-import whoami
```

dry-run の結果とアカウント名を示し、次の形で承認を求める：「<アカウント名> に <N> 曲の高評価を付けます（うち Premium 限定 <P> 曲）。未決定 <M> 曲・スキップ <K> 曲は対象外です。実行してよいですか？」

承認されたら、次のコマンドを実行する。

```sh
ytm-import apply --execute    # バックグラウンドで実行（1 曲あたり約 1 秒）
```

- 進捗は `grep "like " data/ytm-import.log | tail` や `ytm-import status` の `liked` で確認する。
- 既に高評価済みの曲には API を呼ばない。付与した曲は記録されるので、再実行しても重複しない。
- 3 回連続で失敗すると中断する。ログの `like FAILED` の内容を要約して伝える。
  - 401 / 403：認証の期限切れ。手順 5 をやり直す。
  - 429：レート制限。時間をおいて再実行する。
- 途中で止まっても、`apply --execute` を再実行すれば続きから再開する。再実行もアカウントへの書き込みなので、再度承認を取る。

## 7. アーティストのフォロー（ユーザーが希望したときだけ）

ユーザーがアーティスト名の一覧を渡したら、次の順に進める。

1. ログインしていない `YTMusicSearch()._search(name, "ja", "artists")` で検索し、アーティストページの `browseId`（`UC…`）を得る（読み取りのみ）。正規化した名前が一致するページが 1 つだけなら確定とする。
2. 裏付けとして、`get_artist` の曲・アルバムと、DB にあるそのアーティストのお気に入りの曲を照らし合わせる。別のアーティストのページに引っ張られないよう、ページ名が元の名前に近いことも条件にする（同じアルバムの共演者のページを選んでしまうことがある）。
3. 名前だけでは決めにくい次のものは、サブエージェントで Web 検索も併用して調べる。
   - 同名の別人（`HY`、`Fluffy`、`Eve` など）
   - キャラクター名義（`○○(CV:△△)`）
   - 連名だけのページ
   - 改名（`GReeeeN` → `GRe4N BOYZ`）
   - ユニットごとのページが無く、1 ページにまとまっているもの
4. 「名前が一致したもの」「表記違い・改名・連名などで提案するもの」「要確認」「ページが無いもの」に分けて表で示す。名前が一致したものをまとめて承認してもらうと早い。
5. 承認された分を `[{"name": …, "channel_id": "UC…"}]` の JSON にしてスクラッチパッドに置く。`ytm-import follow <file>` で dry-run を確認してから `ytm-import follow <file> --execute` を実行する。すでにフォロー済みのアーティストは飛ばされる。

YouTube Music でアーティストをフォローすると、YouTube でもそのチャンネルを登録したことになる。承認を取るときに、このことを伝える。

## 終わったら

- 結果の要約を伝える：追加した曲数、既に高評価済みだった曲数、スキップ・未決定の曲数。
- 残った未決定の曲は `ytm-import export out.csv` で一覧にできることを伝える。
- 認証ファイルを削除し、YouTube Music からログアウトしておくよう勧める（Cookie の無効化）：`! rm ~/.config/ytm-import/browser.json`
- 曲が増えたら CSV を `import` し直せば、追加分だけを移せることを伝える。
